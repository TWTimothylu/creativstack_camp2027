1. 在指定 Drive 資料夾建立 Google Apps Script 專案，加入 Code.gs、Catalog.gs 與 appsscript.json。
2. 如已有報名管理表，在 Script Properties 設定 SHEET_ID。若沒有，執行 setup() 將建立「2027冬令營｜私人報名管理」並移到指定資料夾：1ouGXc0d-3iIANtWskI8l14NjLfAqjwhR。確認共用為「限制」；setup 不會主動改變權限。
3. 執行 setup()，由帳號擁有人審閱 Google 要求的 Drive、試算表、寄信與觸發器授權。建立五分鐘通知處理觸發器。
4. Script Properties 設定 ADMIN_EMAIL（管理員指定的收件地址）、CONSENT_VERSION（正式條款版本）、REGISTRATION_OPEN=false。不可從 Git 設定推定管理員信箱。
5. 部署為網頁應用程式，以擁有人執行，訪問對象為任何人。僅收件服務可公開，試算表保持限制。記錄部署 /exec 網址。
6. 先建立獨立測試表與測試部署，將測試前端 endpoint 指向該部署。設定同意版本，使用管理員指定測試信箱驗收。不要把測試紀錄寫入正式表，也不要寄信至未指定的信箱。
7. 驗證：匿名及多 Google 帳號下 POST 可取得 JSON 回應；保存、相同請求重送只一列、斷線重試、兩種方案、早托、資格拒絕、截止、關閉收件、家長及管理員兩個收件端。若 Apps Script 跨來源回應不符預期，需修正傳輸層後再開放，不可用 no-cors 不透明回應當成功。
8. 家長及管理員信分別記錄待寄送／寄送中／已交寄／寄送失敗／待人工確認。已交寄不代表送達；退信須由管理員檢查信箱並更新狀態。已交寄但未收到時，不直接重送，先查退信與實際收件。
9. 正式退費、戶外安排及個資保存期限確認後，更新表單文案與 CONSENT_VERSION。設定 public/config.js 的 endpoint 及 registrationOpen=true，後台 REGISTRATION_OPEN=true，再發布前後端。

## 管理規則

- 收件不自動佔位。處理狀態由老師更新為待聯絡、待確認、待繳費、已確認、候補、取消等。
- 早托每日期 100 元；費用只採伺服器共用目錄計算。
- 相同請求 ID 以資料指紋比對；逾時請使用同一份資料重試。
- 通知失敗最多三次，每次至少隔十五分鐘。寄送中中斷改為待人工確認，不自動重寄。
- 對同一 Email 的每小時三筆限制只提供基本濫用限制，正式公開前應依流量評估額外防機器人保護。
- Apps Script / Sheet 並非交易式資料庫；保存後回應中斷用同一請求 ID 查找，避免重複。報名數增加時宜另行評估資料庫與服務配額。
- 請勿手動排序後台資料的部分欄位或修改系統編號與請求 ID。
